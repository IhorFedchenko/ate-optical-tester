# ATE Optical Tester

Автоматизований випробувальний комплекс (ATE) для діагностики та валідації активних оптичних каналів зв'язку (UART / CRSF, PAL Video).

## Апаратне підключення (Pinout)

| Модуль / Периферія | Вхід / Вихід | Пін ESP32 | Примітка |
| :--- | :--- | :--- | :--- |
| **UART1 (TX)** | Output | GPIO 17 | Вихід CRSF на оптичний передавач (FMC1) |
| **UART1 (RX)** | Input | GPIO 16 | Резервний / Сервісний RX1 |
| **UART2 (RX)** | Input | GPIO 23 | Вхід CRSF з оптичного приймача (FMC2) |
| **UART2 (TX)** | Output | GPIO 22 | Резервний / Сервісний TX2 |
| **Status LED** | Output | GPIO 2 | Індикатор стану (неблокуючий Blink 500 ms) |
| **Debug Serial** | USB / UART0 | TX0 / RX0 | Швидкість відладки 460 800 baud |

## Архітектура та бізнес-логіка генерації та валідації кадрів CRSF

Даний модуль призначений для автономного формування, передачі, прийому та валідації кадрів протоколу CRSF через оптичний канал зв'язку. Система працює на швидкості **400 000 baud** із фіксованим часовим каденсом **250 Hz** (період прямування кадрів $\tau = 4.0\text{ ms}$).

### 1. Генерація та формування кадрів (UART1 → FMC1)
* **Формат кадру:** Формується стандартний кадр каналів керування (`0x16` RC Channels Frame) загальною довжиною 26 байтів:
  * **Header (3 байти):** Sync Byte (`0xC8`), Length (`0x18`), Frame Type (`0x16`).
  * **Payload (22 байти):** Дані 16 каналів керування, упаковані за 11-бітною схемою (роздільна здатність 2048 відліків).
  * **Checksum (1 байт):** Контрольна сума **CRC8** (поліном `0xD5`, початковий стан `0x00`), обчислена для блоку `Type + Payload`.
* **Часовий регламент:** У режимі автономного генератора відправка пакетів у `Serial1` здійснюється за циклічним таймером з періодом **4000 µs** (±10 µs джиттер).

### 2. Прийом, парсинг та валідація (FMC2 → UART2)
* **Декодування потоку:** Приймальний буфер `Serial2` обробляє вхідний byte-stream та виконує пошук стартового байта `0xC8`.
* **Верифікація цілісності:** Після накопичення кадру заданої довжини здійснюється розрахунок CRC8 для отриманого блоку та порівняння з оригінальним контрольним байтом:
  * **Успішна валідація (`validFrames`):** При збігу CRC8 кадр передається на декодування каналів, лічильник успішних кадрів інкрементується.
  * **Помилка кадру (`corruptedFrames`):** При розбіжності CRC8 або порушенні структури пакет відкидається, інкрементується лічильник апаратних/оптичних збоїв.

### 3. Розрахунок метрик якості лінії та телеметрія
* **Вимірювання частоти (Packet Rate):** Розраховується на основі дельти часу ($\Delta t$) між надходженнями суміжних валідних кадрів через `micros()`. Nominal: $250\text{ Hz}$ ($\Delta t \approx 4000\,\mu\text{s}$).
* **Детекція втрат (Packet Loss):** Фіксується за умов перевищення таймауту очікування кадру ($t_{wait} > 12\text{ ms}$, що еквівалентно пропуску 3 кадрів поспіль).
* **Оцінка якості каналу (Link Quality & BER):** 
  * **LQ (%):** Відношення кількості валідних кадрів до загальної кількості очікуваних за часове вікно (ковзне вікно 100 кадрів).
  * **BER (Bit Error Rate):** Статистична оцінка бітових спотворень на основі відкинутих за CRC кадрів за сумарний обсяг переданих даних.

## Програмна структура модулів

* `main.cpp` — Головна точка входу, ініціалізація периферії та виконання основного неблокуючого циклу `loop()`.
* `crsf_service.cpp / .h` — Обробка UART (Serial1 / Serial2), генератор кадрів 250 Гц, парсер та обчислення CRC8.
* `metrics.cpp / .h` — Накопичувальний стан телеметрії (`g_metrics`), розрахунок RTT, Link Quality, Packet Loss та автостоп на 3 750 пакетах (15 с).
* `web_server.cpp / .h` — Ініціалізація SoftAP, асинхронний HTTP-сервер на базі `ESPAsyncWebServer` та маршрутизація REST API.
* `index_html.h` — Односторінковий WebUI (HTML5, CSS3, JS ES6) із циклічним опитуванням метрик кожні 250 мс.
* `status_led.cpp / .h` — Модуль фонової індикації стану роботи пристрою.
